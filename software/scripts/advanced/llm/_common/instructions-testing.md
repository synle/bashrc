# Test Quality

Read before writing, reviewing, or trusting a test. Governs evidence strength; Validation Cadence governs check timing and scope. Epistemic Honesty and safety rules remain binding. Rules are named, not numbered.

## What a test asserts

- **Test behavior, not implementation.** Assert a real caller's result: value, status and body, persisted state, event, or generated artifact. Choose the smallest stable public seam that can catch the defect. Private exports, internal call order, helper invocation counts, or six layers of mocks usually signal a misplaced boundary; report that design pressure instead of widening visibility for a test.
- **A test that passes before the fix is not a regression test.** Observe it fail against the unfixed behavior and pass with the fix. The red result must show the intended failure, not an import error, invalid fixture, typo, or uncollected test. Use a safe scoped revert or mutation for an after-the-fact test; never overwrite unrelated edits.
- **Expected values come from the contract.** Derive outcomes from specification, caller requirement, protocol, or independent calculation, not current implementation output. For legacy refactors, label characterization tests pinning current behavior, including known oddities; separate intentional behavior changes.
- **Assert values, not the absence of an explosion.** Check exact meaningful results and full collections, including count, order, and forbidden entries. Do not replace a known value with truthiness, an arbitrary string matcher, or `not.toThrow()`. Relax only genuinely nondeterministic fields and assert their allowed shape.
- **Don't mock what you don't own.** Put external SDK/protocol interactions behind an adapter the project owns, mock that seam, and cover the real integration separately. Recorded external responses need provenance and refresh on upgrades. Do not add a wrapper solely to satisfy a test when an existing owned seam fits.
- **A boundary mock has two sides.** Assert the outgoing payload, authorization-relevant fields, and idempotency key as well as the observable effect of the response. Keep owned business logic real. A canned response echoed by the assertion tests the mock, not the system.
- **Rejected work leaves no effects.** Verify the error and every relevant absence: unchanged state, no write, no event, and no external action. Exercise inputs that reach the intended guard; an earlier validation failure does not test a later rejection branch.
- **Use the artifact's real consumer.** Execute or parse generated scripts, installers, wrappers, and configuration where practical. Assert both process status and meaningful output/readback; an exit code of zero or a matching string alone can hide broken generated behavior.
- **Consumer coverage is separate.** A green local suite never substitutes for the downstream audit required before removal or renaming. Trace dynamic, runtime, and cross-service consumers, especially silent fallback or permission degradation.

## How a test is shaped

- **Discover before adding.** Use the existing runner, factory patterns, file layout, and public seams. Run a targeted baseline before edits and record pre-existing failures separately. Place pure logic at unit level, wiring/contracts at integration level, and only necessary real user flows at end-to-end level; do not introduce another framework without approval.
- **One behavioral reason to fail.** Name condition and expected outcome, not the ticket. Multiple assertions may prove one invariant; separate unrelated scenarios. Keep expectations literal: no branches or implementation-derived formulas. Table-driven cases contain explicit inputs and expected outputs.
- **Case inventory before implementation.** Enumerate happy path, empty/zero/one/many/max, lower and upper bounds, absent versus present-but-falsy, duplicate and reordered values, Unicode, and every handled dependency/error branch. For states/enums, compare declared values with each consumer's branches so an unhandled state cannot hide behind a common happy path.
- **Hostile input reaches the right seam.** Include spaces, quotes, slashes, backslashes, newlines, emoji, right-to-left text, oversized values, traversal attempts, and absolute paths where relevant. Parsers of untrusted bytes get property/fuzz coverage; retain failing inputs as regression seeds. Bound fuzz execution and isolate its state.
- **Paired transformations need independent evidence.** Test encode/decode and serialize/parse round trips over generated valid empty, maximal, and non-ASCII inputs. Also check known vectors independently: inverse functions can share the same bug and still round-trip.
- **Each test owns its data.** Use per-test factories and unique resource names, identifiers, folders, and ports. Do not share mutable seeds or rely on test order. Persistent tests register teardown immediately after creation using the returned resource identifier; readback failure must not skip cleanup. Run shuffled under two seeds and verify the order actually differs before claiming independence.
- **Deterministic or deleted.** Inject or fix clocks, randomness, iteration order, and environment; await observable conditions with deadlines instead of sleeping. Treat a rerun-only pass as a defect. Quarantine requires a linked issue and a date, never silent retries until green; do not delete a meaningful test merely because it exposed a race.
- **Keep feedback affordable.** Ordinary unit tests target under 100 ms each and unit spec files under 10 seconds locally where practical. Label subprocess, integration, browser, network, and build suites clearly. Investigate slow checks instead of inflating global timeouts.
- **Coverage floor for code changes.** Require at least **80% changed-code line coverage and 80% changed-code branch coverage** wherever each metric is available; stricter repository or CI thresholds win. Report the diff measurement, not only project coverage. When a metric cannot be reported, use the closest meaningful changed-code evidence and name the gap; never claim an unmeasured threshold passed. Coverage identifies missing behavior, not a quota for weak assertions.
- **Use mutation as a scoped diagnostic.** A branch flip, removed guard, or changed result should make the relevant assertion fail. Investigate surviving meaningful mutations in risky code; do not add a new tool or run a repository-wide mutation campaign without a concrete need. Equivalent mutations are not behavioral gaps.
- **Report the actual run.** Separate passed, failed, errored, and skipped counts; distinguish new tests from existing checks. Name command, scope, result, red/green proof, and uncovered cases. A required test that cannot run is a failed completion condition, not a pass; explain missing OS, service, credential, or browser without exposing secrets.
