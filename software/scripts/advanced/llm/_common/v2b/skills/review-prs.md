[Sy] Review OTHER PEOPLE'S open pull requests — you act as the **reviewer**, not the author. Run `/sy-review-pr` on every open PR in scope. Find matching PRs, rank attention owed, and dispatch **all at once, in parallel background jobs**. Delegate skip checks, author flags, diff review, verdict, and posting to `/sy-review-pr`. Assign one worker per PR while slots remain. **Enroll and queue surplus PRs by rank** for the next released slot. Review every resolved PR in this same run. The run works a fixed time budget, polling each PR cheaply and reviewing it whenever its state moves. Repo-, language-, and framework-agnostic.

**Whose PRs, and what this does to them — the one distinction to get right.** This command reviews **teammates' and bots' PRs**: it reads a diff someone else wrote and leaves a verdict (APPROVE / COMMENT / REQUEST_CHANGES) plus line comments. It **never pushes code, never syncs a branch, never fixes CI, and never merges** — everything it produces is feedback for that PR's author to act on. The sibling `/sy-babysit-prs` is the opposite in every one of those respects: it works **your own** PRs and changes them. If the ask is "get my PRs green / merged / caught up with main", that is `/sy-babysit-prs`, not this. Reviewing your own PR is a no-op worth refusing — you cannot approve it and there is nobody to hand the feedback to.

**Recommended order.** Run `/sy-review-prs` first (verdict pass — no code changes), then `/sy-babysit-prs` (apply fixes, drive CI green). Reversing wastes babysit cycles on PRs that would otherwise be requested-changes and rewritten. Both commands run the same budgeted polling cadence, so both are long-running fan-outs by design.

Argument: $ARGUMENTS (optional — scope filter; see "Resolving scope" below). Inside a git checkout, default to **all open PRs in the current repo authored by anyone EXCEPT me**. Exclude your PRs unless explicitly named with `me` / `mine` / `self` or your handle. Reviewing serves other authors. Outside a git checkout, no repo scope exists. Fall back to `--author=@me` and explicitly announce that this default selects your own PRs.

## Execution mode

Background agents are default. Resolve, sort, announce, and assign the complete PR set first, then dispatch the existing slot jobs in parallel and await every dispatched or resumed job before the turn ends. Explicit foreground signals are `foreground`, `fg`, `inline`, `blocking`, `synchronous`, `sync`, or `wait`. Strip the token. Preserve reviewer-lens ranking and queue order. Execute enrolled PRs inline in that order, without background agents. Never change scope, sorting, enrollment, worktree reuse, state checkpoints, or pass cadence based on mode.

## Steps

1. **Resolve scope.** Parse `$ARGUMENTS` and build the `gh search prs` call:
   - **Empty `$ARGUMENTS`** — if invoked from inside a git checkout, default to the current repo (resolve via `git remote get-url origin` → `<owner>/<repo>`) and **every author except you**: `gh search prs --repo <owner>/<repo> --state=open -- -author:@me`. Reviewing serves other authors. Exclude your PRs unless explicitly requested by name. Report how many you excluded; never silently shorten the count. Outside a repo, fall back to `--author=@me`. **Announce that the default selected your own PRs**. Mention that `/sy-babysit-prs` was probably intended.
   - **`me` / `mine` / `self`** (case-insensitive) → `--author=@me`. Honor explicit requests over that exclusion. Note once that self-review produces neither approval nor an audience. Name `/sy-babysit-prs` as the command that acts on your PRs.
   - **`<github-handle>`** (single bare token, no spaces) → `--author=<handle>`.
   - **`<full name>`** (multiple tokens, no slashes) → resolve via `gh api "search/users?q=<name>" --jq '.items[0].login'`, confirm with the user, then `--author=<resolved-handle>`.
   - **`<owner>/<repo>`** (single token containing `/`) → `--repo <owner>/<repo>`. Multiple `<owner>/<repo>` tokens (comma- or space-separated) → fan out one `gh search prs` call per repo and union the results.
   - **`org:<org-name>`** → `gh search prs --owner=<org-name> --state=open`.
   - **Combined** — repo / author tokens compose: e.g. `acme/api,acme/web alice` → search both repos for PRs by `alice`.
   - **Repo list** — treat workspace bundles such as `myapp-frontend`, `myapp-backend`, or `myapp-lib` as multiple `<owner>/<repo>` tokens. Resolve each repo. For bare names, ask for the owner once and reuse it across the list.

2. **Fetch PRs:**
   `gh search prs <scope-flags> --state=open --limit 1000 --json number,title,repository,isDraft,url,createdAt,updatedAt,author`

   Then, for stack detection and worktree paths, one follow-up per PR: `gh pr view <url> --json headRefName,baseRefName`. **`gh search prs` has no `headRefName` / `baseRefName` field** and **`gh pr view` has no `repository` field** — see the `gh` field traps in `/sy-list-prs` (Fetch PR data). Without explicit `--limit`, search returns only 30, silently stranding the tail before enrollment. If count equals the limit, report possible truncation.

3. **Announce:** Tell the user how many open PRs were found and list them (repo, PR number, title, author). Resolve yourself with `gh api user --jq .login`. If any PR has another author, lead with `Mixed authors: <handle> (N), …` and show authors on every row. Self-review and teammate review differ. Default scope here includes all authors in the current repo. Skip PRs already filtered out by `/sy-review-pr`'s own skip rules in the per-PR step — don't pre-filter here.

4. **Concurrent-migration cross-check — always, whatever the scope.** Run this BEFORE dispatching review jobs. Concurrent jobs cannot receive shared context after launch. Each per-PR job sees only its own branch. **There is no scope condition on this step:** same-repo PRs share one migration DAG, so a single-repo scope is the _most_ likely place two migrations collide, not the least.

- **Scan every open PR in each repo the scope touches — not just the PRs being reviewed.** `gh pr list --repo <owner/repo> --state open --json number,url,title,headRefName,author,autoMergeRequest --limit 100`, then `gh pr diff <n> --repo <owner/repo> --name-only` on each to spot migration files (detection paths: `/sy-sync-pr-branch` Step 7, as `/sy-review-pr`'s Migration checks defer to). A PR outside the review scope still collides with one inside it, and a PR with automerge already on can land mid-run with nobody watching.
- **Record each repo's current migration head at dispatch** and pass it to every affected job. This distinguishes initial staleness from mid-run head movement without reconstructing dispatch state every pass.
- **For two or more open migration PRs, announce conflict pairs upfront, including each PR's automerge state**. Pass pairings to affected jobs for symmetrical author flags (`/sy-review-pr` Check 2). Reviews never re-parent or reorder anything — this is coordination the authors act on.

Service every PR for the whole run budget (`/sy-review-pr` Step 10, or the dispatcher's clock for multiple assignments). Agent cells carry `(pass N · <HH:MM> left)` and one state: `🔄 IN PROGRESS`, `⏸️ WAITING`, `⏸️ WAITING_AFTER_SKIP`, `✅ COMPLETED`, `⏭️ SKIPPED`, `❌ FAILED`.

4b. **Enroll every PR, rank them, then fill the worker slots from the top of the queue — before anything launches.** The harness caps how many background jobs run **at once**; it does not cap how many PRs the run covers. Identical to `/sy-babysit-prs` Step 3b — same ranking, same four ledger states, same guarantee:

Resolve capacity in this precedence order: user-supplied `cap=<positive-int>` or prose cap; otherwise the harness instructions' **concurrency cap**, if declared. Otherwise use no cap: `S = N`, one job per PR. Reject anything that is not a positive integer — fall back to the next source down and say so, because `S = 0` leaves nothing able to run. **Strip `cap=` from `$ARGUMENTS` before scope parsing**.   - **`k == 0` is a launch failure, not a cap discovery.** Report it and stop — `S = 0` would "recover" into launching nothing.
  - **Cancel the `k` that started and confirm each is terminated before relaunching**; two jobs reviewing one PR double-post.
  - **Seed the relaunched slots with each PR's `## State` block from the ledger**, so a review already posted by a cancelled job is not posted again.

- **Rank all `N` resolved PRs by work owed through the REVIEWER lens**. Use `/sy-list-prs`'s canonical `## Work-owed ranking`: one table, two lenses, attention keys, activity bands, queue aging, and tiebreakers. Request scheduler data with `pr_list --json --activity`; do not change ordinary `pr_list` calls. Do not restate or re-derive any of it here; read it there. Use the **reviewer lens**, not the default author lens: the `R0` / `R1` attention keys sort first, then reviewer tier, then active before stale and newest `activityAt` first. Scoring `R1` needs one extra `gh pr view <url> --json body,comments,reviews,reviewRequests,latestReviews` per PR — fold it into the Step 2 follow-up call rather than making a second pass over the set. Say which lens you used, name every `R0` / `R1` reason, and report any stale PR promoted by queue aging. Ranking decides **order only** — it never removes a PR from the set, and it never substitutes for `/sy-review-pr`'s own skip rules.
- **Launch `min(N, S)` workers from the top of the ranked queue, all at once**, so the highest-ranked PRs each get their own worker immediately. When a worker returns, its PR moves to `watching` or back to `queued`, the slot frees, and the next PR by rank takes it.
- **Every PR is enrolled before the first job launches.** A resolved PR missing from the ledger is a bug in this step, not a backlog — go back and enroll it. `queued` is not stranded: it is next in line, and the ledger says so.
- **Report the ledger at dispatch** — every PR with its tier and starting state. This is the artifact that proves nothing was stranded.
- **Warn — do not refuse — when the queue is more than 3× the slot count.** Say so, name the number, and carry on; reviewing all of them slowly beats reviewing `S` of them and abandoning the rest.

   - **Adopt before you dispatch — a slot is a long-lived job, not a per-round spawn.** Every slot job carries the stable key `sy-review-prs:slot<i>`, and every PR it holds carries `sy-review-pr:<owner>/<repo>#<number>` (see _A job is addressed by a stable key_). **Enumerate running and idle jobs before launch and match stable keys**. Never redispatch a slot with a live owner. Leave running owners alone; resume idle owners with follow-up turns carrying their next round. Only a key with no live owner gets a new job. **Record returned resume handles in the ledger immediately**. Only those handles address jobs in later rounds; you cannot reconstruct them. A ledger without handles forces fresh spawns despite this rule. This is what makes re-invoking `/sy-review-prs` while a fan-out is still in flight safe: it re-attaches to the running slots rather than doubling every lane and posting every review twice. A PR found under two live jobs is resolved by keeping the older and cancelling the newer, reported explicitly.
   - **Emit every slot job in ONE assistant message with `slot_count` tool calls in that same message.** One sub-agent / Task / background-shell invocation per slot, all in a single block. A second message per slot is a sequential loop wearing a parallel costume — that is the failure mode this section exists to prevent.

   - **One slot = one job = one lane. When `N ≤ S`, one slot holds exactly one PR** and this is the classic one-job-per-PR fan-out. Multiple PRs share a slot only when PRs outnumber slots. This is the _only_ exception to "never a single job that iterates the PR list". Iterate **only assigned PRs**, never the whole list or a self-selected list.

   - **Give every job an identifying label, and a PR-specialized worker when one exists.** Where the environment lets a dispatched job carry a short label, set it to `<PR number> - <head branch> - <author>` for the PR that job starts on. Where the environment offers a worker specialized for reviewing someone else's pull request, dispatch to that one rather than the generic default. Both are cosmetic-only: a run that can do neither is not degraded, and neither ever changes scope, ranking, assignment, or cadence. They exist because a board of identically-named workers is unreadable the moment a fan-out exceeds two slots — the operator cannot tell which lane stalled.
   - **Each slot job's prompt is self-contained.** Explicitly pass its **ordered assignment list** with each PR's tier. Include each PR's full URL, PR number, resolved `<owner>/<repo>`, and Step 4 migration-conflict pairing. Resolve identity from `git remote get-url origin`, never folder names. Sub-agents start with a fresh context — anything you don't pass, they don't have.

   **What a worker does — one pass per round, inside the job that already owns the slot.** Dispatch each slot job **once** and resume it for later rounds. Rotate **PR assignments**, never terminate or respawn the job. See _A pass that runs inside a job runs in that job_. A worker still runs exactly one pass per PR per round and reports, so it never sits on a slot waiting for a sleep to elapse. **The dispatcher owns the cadence:**
   - **Invoke `/sy-review-pr <PR-URL> pass=single round=<n>` per pass**. Add `last=true` on the final pass. **Paste the previous `## State` block into the prompt under `## Prior state`**. Omit that heading on the first pass. Resumed jobs retaining prior-round context need the block only as a cross-check. `pass=single` makes the per-PR command run one pass and return instead of owning the clock itself; the prior-state block is what stops pass 2 from restating pass 1. Dropping either turns a long run into a series of disconnected first passes.
   - **Run every pass inside the slot job itself — never dispatch a sub-agent per pass, and never a fresh job per round.** `pass=single` forces `/sy-review-pr` inline (its Execution mode), and so does the fact that the slot job is already a dispatched job; either alone is sufficient. Round N+1 **resumes** round N's slot job through a follow-up turn. Preserve its warm context: worktrees, read threads, and counters. Spawning a child per PR per round creates `PRs × rounds` agents: 30 for a 3-PR slot over 10 rounds. Each starts empty, re-fetches the diff, re-reads threads for deduplication, and charges another concurrency slot. A round number in a job's label beside a fresh session is the visible symptom that this was skipped. **A pass is one unit of work; the job and the ledger are the long-lived things.** The `## State` block a worker hands back is what seeds its next pass and any replacement, which is why it is never dropped.
   - **Await every job dispatched or resumed in a turn before that turn ends** (see _Never end a turn with a dispatched job still in flight_). The dispatcher records child completion when children return. Ending a turn with an open round freezes completed jobs at "running" on the board. Stale rows then look like wedged jobs. Never issue a round the run has no time left to await: on the deadline, finish the round in flight and report, rather than starting one more.
   - **The dispatcher owns the clock — the run budget is `<<SY_PR_RUN_BUDGET_ROUNDS>>` rounds (one round = one keepalive interval)** from launch, shared by the whole set. Run full passes for fingerprint changes, first service, or keepalive at least every `<<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` seconds. Also run one final pass before deadline. There is no per-PR pass quota.
   - **Re-rank every pulse** using the full reviewer lens, attention keys, `activityAt`, and queue aging. Fresh commits, comments, reviews, CI transitions, or `@`-mentions outrank idle peers within the same urgency tier. `R0` stays first, then `R1`, then reviewer tier, then active before stale and newest `activityAt` first. A stale PR waiting through `3` queue selections, or `1` full run without a pass, gets an aging promotion within its current band and tier. **Ranking sets which queued PR takes the next free slot — never whether a PR is reviewed at all.** Report the band and aging count in the ledger.
   - **A PR that reaches a terminal state leaves the rotation** (`MERGED` / `CLOSED` only). Report it and stop scheduling it. A skipped pass is **not** terminal — draft, WIP, already-reviewed, and blocked-by-another-reviewer stay enrolled and are re-passed the moment their fingerprint moves. A `NEEDS_USER` PR is **not** terminal either — it moves to `watching`, keeps its probe and keepalive, and returns to the queue when revalidation says `cleared`.
   - **Never preempt a running pass.** New inbound work on an `active` PR marks it `dirty_after_pass` and re-queues it at the head the moment its worker returns.
   - **If a whole slot job dies, relaunch that slot — do not fold its PRs into a live one.** A dead slot frees exactly its used capacity, allowing replacement without exceeding `S`. Moving its PRs to a neighbor doubles that lane's round length and violates "a slot's assignment never changes mid-run". **Confirm death before replacement**. A finished turn means _idle_, not dead. Resume idle slots with follow-up turns carrying their next round, preserving everything read and posted. See _Resume an idle job; relaunch only a dead one_. Only a failed, cancelled, or gone job gets a replacement, launched with the dead slot's **remaining** PRs plus a checkpoint from the ledger — each PR's last `## State` block. **Resume each PR from its own `completed_round + 1`**, never a run-wide round number. Re-queue the interrupted PR at the head with its last `## State`. Preserve every other PR's counter. No capacity to relaunch into (the run is being torn down) means reporting those PRs with their per-PR pass counts, never as reviewed.
   - **Report each PR's fingerprint and `externally_blocked` back with its `## State` block, every pass.** That is what lets the dispatcher move it to `watching` and stop paying a worker for it (Step 5b). A worker never decides to park itself — it reports state; the dispatcher schedules.

   The per-PR skill owns the full behavior:
   - Skip drafts / WIP / DO NOT MERGE / already-reviewed-no-new-commits / blocked-by-other-reviewer.
   - Load repo rules and culture context (`CLAUDE.md` / `AGENTS.md` / `CONTRIBUTING.md` / `.cursorrules`).
   - Pre-flight author flags (diff-vs-description mismatch, merge conflict with base, failing CI with run-URL pinpoint, migration coordination) as PR comments.
   - De-duplicate against existing review threads and reactions from humans, bots, and your past reviews. 👍 covered findings. Reply in-thread with missing-case deltas. Post top-level comments only for genuinely new findings.
   - Read the diff (or just the new commits for stale-approval re-reviews).
   - Pick verdict — APPROVE / COMMENT (default bias) / REQUEST_CHANGES (show-stoppers only). Cap at COMMENT when another reviewer's `REQUEST_CHANGES` is open or CI is failing.
   - Post the review — or post nothing at all when a re-review turns up nothing new.

   Review is read-only — it works off `gh pr diff` / `gh api` and needs no checkout, so parallel jobs never collide. **Use disk checkouts only when review requires them**, such as builds, tree tools, or reproductions. Use `$HOME/.worktrees/<owner>/<repo>/<sanitized-branch>` (One rigid worktree path) through `WT="$(worktree_create "$BR")"`. Reuse existing linked worktrees on that branch; otherwise create one there. Never `git checkout` / `git switch` / `gh pr checkout` in the user's primary checkout (see Never do PR-branch work in the primary checkout). Never sit silent or busy-poll jobs. The Step 5b fingerprint probes ride on it, at the `<<SY_PR_POLL_INTERVAL_SECONDS>>`-second cadence.

- **Render with `/sy-list-prs pingpong <same-scope-token>`, passing the current agent ledger.** Same scope token as Step 4a so every pulse covers exactly the dispatched set.
- **Refresh the Status column from GitHub, not from the jobs.** Re-run the cheap `gh pr view` status calls `/sy-list-prs` already uses. **Never message or interrupt a running job to ask its progress** — that wakes a running pass and corrupts its cadence. 5b. **Watching — a PR with nothing left to review is polled by the dispatcher and holds no worker.** A review fan-out otherwise spends its back half paying a full agent per PR to re-read an unchanged diff and reach Step 9's stop-early gate again. Watching replaces those agents with two read-only `gh` calls per PR, folded into the pulse's existing fetch, and requeues the PR the moment its state moves. **Identical to `/sy-babysit-prs` Step 4b — same move-to-watching rule, same stand-down-with-state-capture, same requeue-on-change, same keepalive, same reporting. Read it there; do not restate or re-derive it here.** The fingerprint itself is defined once in `/sy-babysit-pr` Step 12a. Two review-specific notes:

- **Move PRs to `watching` when `## State` reports `externally_blocked`**. The per-PR job applies `/sy-review-pr` Step 10a: stop-early no-op, draft / WIP skip, no new commits, or another reviewer's block. Never second-guess its decision here. Watching is per PR, so one blocked PR frees its slot immediately.
- **`headRefOid` is what requeues a watched review most often.** Pushes make diffs worth re-reading. Watching detects new commits as quickly as live workers would. Intervening rounds cost two `gh` calls instead of an agent.

5c. **The run ends when the rounds run out — never when the work does.** A review fan-out is sleep-dominated by design, so "nothing changed" is the normal shape of most rounds and is never a stopping condition.

- **Every wait is a real blocking `sleep` command.** The fingerprint poll is `sleep <<SY_PR_POLL_INTERVAL_SECONDS>>`; the dispatcher's pulse gap is `sleep 600`. One foreground, self-terminating command per wait — never a note in the report claiming time passed, never a shortened sleep, never a busy-poll. A harness timeout below the target re-issues `sleep` for the remainder until the full interval has actually elapsed.
- **A dispatcher with no detached-job facility runs the loop inline — it does not cancel it.** None of these claims describes terminal state:
  - "Background jobs do not outlive the turn".
  - "No wall clock has elapsed".
  - "Two probes were byte-identical".
  - "The set is quiescent, re-invoke me later".
    Each describes a run that should keep polling. Fall back to running the loop in the foreground with real sleeps, keeping the same ranking, enrollment, cadence, and ledger. Ending early with budget still left is the failure this command exists to prevent.
- **Stop the run on the deadline, on a fully terminal ledger (explicit-ref scope only), or on an unreachable service.** The budget is `<<SY_PR_RUN_BUDGET_ROUNDS>>` rounds (one round = one keepalive interval), after which every non-terminal PR gets one final full pass. GitHub or the model service staying unreachable for `<<SY_PR_RETRY_MAX_FAILURES>>` consecutive attempts `<<SY_PR_RETRY_INTERVAL_SECONDS>>` seconds apart also ends the run — report `"GitHub or model service unreachable — stopping with resumable state"`, never a local network cause you cannot verify. On every stop, write the ledger and each PR's `## State` block to its `<<LLM_ROOT_FOLDER>>/pr_reviews/` memory so a fresh invocation resumes instead of restarting.
- **Re-resolve the PR set at every pulse, with the same scope token.** The set is not frozen at dispatch: PRs open, merge, close, get marked ready, and pick up new commits mid-run. A newly opened in-scope PR is enrolled and ranked into the queue on the pulse that finds it; a `MERGED` / `CLOSED` one drops out. That is the whole reason an unchanged round is still worth running.
- **A worker's stop-and-ask is surfaced to the operator, and revalidated before it is repeated.** Park PRs returning `needs_user` in `## State` as `watching`. Stop review work but retain probes and keepalives. Show the operator; sub-agent reports can scroll past. Copy the block verbatim into the ledger and mark the row `NEEDS_USER`. Repeat its reason, exact message, and `Next:` line in every pulse and final report. Never open a prompt, never block waiting on an answer, and never express it on GitHub. **Every PR being terminal or `NEEDS_USER` is not itself a stop condition**. Print outstanding questions together, then keep sleeping and probing until deadline. Fingerprint changes or keepalives dispatch `/sy-review-pr` Step 2b revalidation. Return `cleared` PRs to the queue. Revalidate startup review-memory claims first. Paste the block into that PR's next pass. Render `/sy-review-pr` Step 2b's verdict, never the stale claim alone.
- **Never close a turn by asking what to do next.** No "want me to continue?", no "re-invoke when time has passed", no handing the ledger back for the user to drive. The only terminal exits are: every PR `MERGED` / `CLOSED` **in explicit-ref scope**, the deadline, or the unreachable-service stop.
- **An empty or fully terminal ledger ends the run only in explicit-ref scope.** When `$ARGUMENTS` named specific PRs, every one `MERGED` / `CLOSED` is terminal. Every other scope is a search (repo, author, org, pwd, empty), and a search that finds nothing now can find something next round. In those modes, zero open PRs or an entirely merged/closed ledger means an **idle round**. Report one line, `sleep` the keepalive, re-resolve scope, and enroll new PRs. Continue until deadline or unreachable-service stop. Never write `Stopping because the only reachable PR merged` in a search scope.

6. **Final report:** Emit the **closing ping-pong** with `/sy-list-prs pingpong <same-scope-token>`, final ledger, and `Next ping-pong: — (final)`. Then summarize each PR:
   - Author, when the set is mixed.
   - Final ledger state and pass count.
   - Verdict: APPROVE / COMMENT / REQUEST_CHANGES / SKIPPED + reason.
   - Author flags posted and cross-PR migration coordination notes.
   - **Every PR that spent time watching**: `github.com/acme/api/pull/51 watched 2h40m — nothing new; 32 probes, 0 worker dispatches`. **Verify and explicitly report review coverage for every resolved PR**. Compare row count with Step 3's announced count. Enrollment must prevent mismatches. Name every zero-pass PR and explain why. A watched PR is a serviced PR: report it as one, never as skipped or missing. The run therefore always brackets itself: pulse at the start (Step 4a), pulse every 10 min (Step 5a), pulse at the end.

   **Status references carry titles.** In the final report, pulse annotations, merged/approved lists, open-findings lists, and any other user-facing PR status, render each PR as `<full PR URL> | [<repo-name>] <current PR title>`. Fetch the title from the same verified PR record used for status; do not invent, shorten, or infer it from the URL. Keep the URL first so the line stays clickable.

   **Findings carry impact summaries.** Group new findings under a heading that states verdict and source when useful, for example `New COMMENT plus observability-query finding:`. Add one short sentence under that heading explaining what changed, whether it blocks merge, and the main risk. Each finding bullet must state the concrete issue or requested action in one sentence, then include the full PR URL and repo-tagged title. Example: `- Query omits failure state, so operators cannot distinguish no data from a failed lookup; https://github.com/acme/widget-store/pull/42 | [widget-store] Add observability query.`

## Rules

- **This command is a dispatcher. The per-PR logic lives in `/sy-review-pr` — do not re-implement it here.**
- **A live job is adopted and resumed, never doubled (Step 5).** Give every slot and PR a stable job key. Enumerate live jobs and match keys before dispatch. Re-invocations must reattach, never duplicate lanes. Two reviewers on one PR duplicate posts, an irreversible workflow failure. A job that finished its turn is **idle, not dead**: resume it with a follow-up turn, replace it only when it is failed, cancelled, or gone. Run passes **inside** their owning jobs. Both `pass=single` and "already inside a dispatched job" force `/sy-review-pr` inline. Child agents per pass multiply agents, diff fetches, and thread scans despite existing job context. Use these canonical rules: _A job is addressed by a stable key_; _Resume an idle job; relaunch only a dead one_. Also follow _A pass that runs inside a job runs in that job_.
- **Every job writes to GitHub — this bulk dispatcher has no report-only mode** (see `/sy-review-pr` Output surface). Verdicts, author flags, line comments, threaded replies, and 👍 reactions land on the PRs themselves; the Step 6 summary reports what was posted, it does not replace posting. Never stop to ask the user whether to post or report, and never route findings to a `/sy-critique-*` command — no such command exists. `/sy-review-pr`'s `dry-run` opt-out supports single-PR, foreground, human-in-the-loop review. **Never dispatch it from this fan-out**. Unattended background batches lack a user to confirm each proposal.
- **The cross-PR migration check runs on every invocation, at any scope, over every open PR in the repos involved (Step 4).** This step is neither multi-repo-only nor limited to reviewed PRs. Same-repo PRs share one migration DAG, making single-repo collisions especially likely. Unwatched PRs can still break default when landing second. The dispatcher is the only thing that can see the whole set — once jobs are in flight they cannot be handed shared context. It coordinates and flags only; re-parenting belongs to the author, via `/sy-babysit-pr`.
- **Parallel means one message, `min(N, S)` tool calls (Step 5 Dispatch mechanics).** The job count is the free-slot count, never the PR count: launching one job per PR past the cap is what gets the launch rejected and strands the tail. If the transcript shows slot jobs starting one message at a time, the fan-out was sequential and must be relaunched.
- **Every resolved PR is enrolled before anything launches — never dropped (Step 4b).** One worker per PR while slots last; past the concurrency cap the surplus is `queued` by rank and takes the next slot a worker releases. A slot is held only by a pass actually running, so a `watching` or `queued` PR costs nothing. A PR that ends the run with zero passes is a bug in this command, not an acceptable outcome.
- **Order comes from the work-owed ranking, defined once in `/sy-list-prs`.** Do not restate tiers, reviewer `R0` / `R1` attention keys, or tiebreakers here. Never invent another ranking or use ranking to skip PRs. Ranking sets service order only, never replacing `/sy-review-pr`'s own skip rules.
- **Draft / `WIP` / `DO NOT MERGE` / `DNM` PRs rank dead last and no attention key lifts them (P6).** Newest arrival or a direct `@`-mention does not promote one — an author marking a PR not-ready outranks both. Still dispatch them and run their passes. Document each pass as a skip that **posts nothing to GitHub**. "Ignored" describes output only; later rounds still catch mid-run readiness changes. Verify both outcomes in Step 6: terminal `⏭️ SKIPPED` with marker reason, and zero posted artifacts. Mid-run, use `⏸️ WAITING_AFTER_SKIP` because markers can disappear between rounds.
- **A worker runs one pass per round and hands the slot to the next PR — the job it runs in is not re-spawned (Step 5).** Run every `/sy-review-pr <url> pass=single` pass **inside** its existing slot job, with prior state pasted in. Round N+1 resumes that job; never dispatch a replacement merely for another round. Workers sleeping through cadence while holding slots recreate starvation inside jobs. Fresh agents per PR per round recreate agent explosion, even with round-number labels.
- **Review all resolved PRs in parallel background jobs — never a sequential for-loop** (see Fan out multi-PR work in parallel). Collect verdicts as jobs finish and report once at the end.
- **Jobs needing disk access use canonical worktrees**: `$HOME/.worktrees/<owner>/<repo>/<sanitized-branch>`, always through `worktree_create` (One rigid worktree path). Never use the primary checkout; see Never do PR-branch work in the primary checkout. Reviews are normally checkout-free; treat a checkout as the exception, not the default.
- **Show the author on every row when the set is mixed** (see Show PR authors). This command defaults to ALL authors in the current repo. Expect mixed sets. Include authors beside verdicts in the final report (Step 6) too.
- **Honor `/sy-review-pr`'s skip rules** — enroll every resolved PR, including drafts/WIP/already-reviewed ones, and let its pass report the skip. While budget remains, use `⏸️ WAITING_AFTER_SKIP`, not terminal `⏭️ SKIPPED`; later passes catch readiness changes. The announced count equals enrolled PRs, not concurrent jobs; Step 4b caps active workers at `min(N, S)`.
- **Every PR is serviced for the whole run budget** (`/sy-review-pr` Step 10, or the dispatcher's clock when it holds several). Never treat the first verdict as a PR's final report, and never cancel a job because the board went quiet — between passes the run is polling by design. `pass=single` is the one sanctioned way to run a lone pass, and only from a driver that is itself honoring the budget (Step 5).
- **Default bias inherits from `/sy-review-pr`**: APPROVE or COMMENT — REQUEST_CHANGES is reserved for show-stoppers only.
- **Silent jobs are a success, not a failure.** A job that posts nothing because the re-review turned up nothing new reports `NO-OP` in the final summary. Don't retry it and don't nudge it into commenting to prove it ran.
- **A PR with nothing left to review is watched by the dispatcher and holds no worker (Step 5b).** Repeated no-op passes are normal during long reviews. Avoid paying agents to rediscover them. Watching costs two read-only `gh` calls per probe, folded into the pulse's existing fetch. Requeue immediately on fingerprint changes, especially new commits. Run keepalive passes at least every `<<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` seconds and once before deadline. Never move a PR to watching mid-pass, and never report a watched PR as a missing one.
- **Ping-pong is mandatory, not optional (Steps 4a / 5a / 6).** Every run pulses before dispatch, every 10 minutes while jobs run, and once at the end. Keep pulses read-only: refresh PR status through `gh` and read existing verdict reports. Never message or interrupt running jobs. Never act on pulse findings inside the pulse.
- **Ping-pong layout is owned by `/sy-list-prs pingpong`.** This command owns and passes the agent ledger: ledger state, pass count, dispatch/pass times, next-check ETA, slot/queue position, and last rendered pulse snapshot. `/sy-list-prs` owns columns, icons, change markers, feature-set grouping, and sorting. Agent cells here carry the `(pass N · <HH:MM> left)` counter — same form as `/sy-babysit-prs`.
- **Multi-repo workspaces** (e.g. a bundle like `myapp-frontend`, `myapp-backend` or `myapp-lib`): pass each repo as a `<owner>/<repo>` token. The cross-PR migration check (Step 4) runs across the full union **before** any job is dispatched, so coordination flags surface before any verdict is posted.
- **Always resolve `<owner>/<repo>` via `git remote get-url origin`, never from the folder name (see Repo Identification).**
- **An idle set is a reason to sleep, not to stop (Step 5c).** Every wait is a real `sleep` command, the PR set is re-resolved every round, and the run never ends with a question to the user. A run that stops with rounds still owed is reported as a failed run.
