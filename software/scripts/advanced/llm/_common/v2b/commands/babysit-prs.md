[Sy] Babysit YOUR OWN open pull requests to the merge line — you act as the **author**, not a reviewer. Run `/sy-babysit-pr` on every open PR in scope. Sync each branch with its base and preserve approval by default. Address only blocker-related review comments for failed CI, base conflicts, stale migration heads, or blocking reviewer requests. `<<SY_PR_REVIEW_CHANGE_THRESHOLD>>` or more unresolved actionable change comments also activates remediation. Fix failing CI and continue until the PR is green and mergeable. Resolve target PRs from `$ARGUMENTS` and rank them by work owed. Dispatch them **all at once, in parallel background jobs**, each in its own git worktree. Assign one job per PR while slots remain. Enroll and queue remaining PRs by rank for the next released slot. Service every resolved PR in this same run.

**Whose PRs, and what this does to them — the one distinction to get right.** This command works on **PRs you authored**, and it **changes them**: it pushes commits, merges the base branch in, replies to review threads, and can enable automerge. Default scope is `@me`; never target a teammate's PR. Pushing to another author's branch rewrites their work. Answering their reviewers speaks for them. The sibling `/sy-review-prs` is the opposite: it reviews **other people's** PRs and only ever leaves feedback. If the ask is "review the team's PRs / give a verdict / leave comments", that is `/sy-review-prs`, not this. Someone else's PR belongs here only when they explicitly hand it over — say whose it is and what you pushed.

**This is the command for "sync all my PRs with main, preserve approval, and fix only blocking failures — all at once, in the background, with worktrees."** Every part of that request already belongs in scope:

- `/sy-babysit-pr` Step 5 delegates sync to `/sy-sync-pr-branch`: default plus the whole ancestor chain for stacks.
- Steps 6–7 activate comment remediation only for failed CI, base merge conflicts, stale migration heads, or active `CHANGES_REQUESTED` reviews.
- `<<SY_PR_REVIEW_CHANGE_THRESHOLD>>` or more unresolved actionable change comments also activates remediation.
- Step 4 below covers background jobs, worktrees, and all-at-once dispatch. Route any plain-English phrasing of that request here — do not hand-roll a loop, and do not call `/sy-sync-pr-branch` yourself first; every job already runs it.

**Recommended order.** Run `/sy-review-prs` first (verdict pass), then `/sy-babysit-prs` (this command). Reversing wastes babysit cycles on PRs that would be requested-changes anyway.

Argument: $ARGUMENTS (optional — selects scope; the first token decides the mode, no mixing). Every mode below stays scoped to **your own** PRs unless a PR is named explicitly.

- **Empty** — babysit every open PR authored by `@me` for git repos at or below cwd, two levels deep (see Repo discovery). (Default behavior.)
- **PWD keyword** — first token (case-insensitive, trimmed) is one of the PWD keyword set defined in `/sy-list-prs`. Scan repos up to 2 child levels below cwd and babysit `@me` open PRs in those repos only.
- **Explicit PR refs** — one or more whitespace-separated PR refs. Each ref is one of:
  - full URL: `https://github.com/<owner>/<repo>/pull/<n>`
  - shorthand: `<owner>/<repo>#<n>`
  - Bare `#<n>` or digits `<n>` require cwd to be a git repo with a GitHub `origin`. Resolve `<owner>/<repo>` via `git remote get-url origin`, never folder names; see Repo Identification.

## Execution mode

Background agents are default. Resolve, sort, announce, and enroll the complete PR set first, then dispatch the existing slot jobs in parallel and await every dispatched or resumed job before the turn ends. Explicit foreground signals are `foreground`, `fg`, `inline`, `blocking`, `synchronous`, `sync`, or `wait`. Strip that token. Preserve author-lens ranking and queue order. Execute enrolled PRs inline in that order, without background agents. Never change scope, sorting, enrollment, worktree reuse, state checkpoints, or pass cadence based on mode.

## Steps

1. **Resolve target PR list from `$ARGUMENTS`.** Pick exactly one branch:

1p. **Drop placeholder drafts before ranking or dispatch.** For every resolved PR URL, fetch `gh pr view <url> --json isDraft,title,url`. If `isDraft` is true **and** the title contains `Placeholder` (case-insensitive), remove it from the babysit set and report it as `skipped placeholder draft pending implementation`. These PRs are intentionally parked before implementation starts and should not consume a slot, probe loop, or watch budget. They re-enter scope only after code lands, the PR is marked ready, and the placeholder markers are gone.

a. **Empty `$ARGUMENTS` or PWD keyword** — delegate to `/sy-list-prs short pwd` (scope = pwd, format = short). Parse the emitted URLs (one full PR URL per line, grouped under `##` headings). **Never pre-filter READY TO MERGE or any other group**. Green PRs still receive slots and passes. `/sy-babysit-pr` Step 4's early-exit makes those passes cheap documented no-ops. Pre-filtering can leave a PR with zero passes, violating Step 3b. "Green right now" does not imply "green in 90 minutes" during a long fan-out. If zero PRs resolve, report it and run idle rounds; see _An empty or fully terminal ledger_. Re-resolve search scope every round. Never end merely because it is empty.

b. **Explicit PR refs** (any other `$ARGUMENTS` — treat as whitespace-separated tokens):

- For each token, normalize to a full PR URL:
  - Full URL → use as-is.
  - `<owner>/<repo>#<n>` → expand to `https://github.com/<owner>/<repo>/pull/<n>`.
  - `#<n>` or bare digits → require cwd to be a git repo; resolve `<owner>/<repo>` via `git remote get-url origin` (never from the folder name), then expand. If cwd is not a git repo, error out naming the unresolvable token and ask the user to use a fully-qualified ref.
  - Anything else (not a URL, shorthand, `#<n>`, or digits) → error out, name the bad token, do NOT silently skip.
- For each resolved URL, fetch metadata to match the search-result shape used downstream:
  `gh pr view <url> --json number,title,headRefName,baseRefName,isDraft,url,createdAt,updatedAt,author`. **`gh pr view` has no `repository` field** (see the `gh` field traps in `/sy-list-prs`) — the owning `<owner>/<repo>` is the one you already resolved from the ref itself.
- De-duplicate by URL.

2. **Announce:** Report scope mode: `pwd scan of <N> repos` for empty/PWD arguments, or `explicit list of <N> PRs`. Report resolved-PR and excluded-placeholder-draft counts. List remaining PRs by repo, PR number, and title. Resolve yourself with `gh api user --jq .login`. If any resolved PR has another author, show authors on every row and explicitly report the split. Explicit-ref mode does not filter authors; accidental babysitting is easy.

   **Also announce the stacks.** Stack detection requires `headRefName` + `baseRefName`. **The PWD path lacks them** because `/sy-list-prs short` skips per-PR branch fetches; see its Fetch PR data notes. Only Step 1b's explicit-refs path already has them. Fill the gap the same way `/sy-review-prs` does: one `gh pr view <url> --json headRefName,baseRefName` per resolved PR, which is also the call whose result the worktree path depends on. Then detect stacks from the set itself: any PR whose `baseRefName` equals another PR's `headRefName` is stacked on it. Chain those links and print each stack bottom-up (`<root link> ← <child link> ← <grandchild link>`), noting that they merge in that order. This is display only — it does not change dispatch (Step 3b still assigns every PR before anything launches) and it never makes one job wait on another.

   **Also announce the waves.** Waves impose merge barriers, not branch parents; see _Hard dependencies phase into waves_. Stack detection cannot see them because every wave PR targets default. Read each resolved PR's body (`gh pr view <url> --json body,isDraft,title`) for a `## Blocked on` section or dependency prose (`depends on <link>`, `blocked by <link>`, `part of <link>`), and resolve each named blocker's real state. Print the waves in merge order with each blocked PR's parked shape (`wave 2: github.com/acme/web/pull/7 (draft, WIP prefix) — blocked on github.com/acme/api/pull/40`). **For `wave <W> - pr <i>/<N>` titles, compare `<i>` with the resolved wave graph and report disagreements**. Flag numbers below lower-wave numbers, duplicates, or stale `<N>` values: these encode creation order, not merge order. See _A sequence number in a title is MERGE order_. Report the corrected positions; the retitle itself is the per-PR job's, on its own pass. **Re-run this check every pulse, not only at dispatch**. Re-resolve the set each time. Mid-run additions, including new slices or reviewer-requested follow-ups, change everyone's ordering and `<N>`. Place it by its dependencies rather than at the end, re-derive the whole order, and name every PR whose position moved. **Give each blocked PR's worker its blocker links** (Step 4). `/sy-babysit-pr` Step 4a needs that promotion context. A worker cannot infer waves from its branch alone. The dispatcher itself never edits a title, never undrafts, and never rewrites a body: promotion is the per-PR job's, on its own pass.

3. **Render the resolved PR set as a table** so the user sees exactly what is about to be babysat. Delegate rendering to `/sy-list-prs table <same-scope-token>`. Both commands accept empty scope, PWD keywords, or explicit refs. Pass the same scope `$ARGUMENTS`, prefixed with `table`. Single source of truth for the table layout lives in `/sy-list-prs`.

3a. **Open the ping-pong pulse — emit the FIRST one before dispatching anything.** Render `/sy-list-prs pingpong <same-scope-token>` with every Agent cell at `⚪ NOT STARTED`. This gives the user a baseline for later pulses. Prevent hour-long silence before a fan-out's first status line. Layout lives in `/sy-list-prs` — do not hand-roll it. **This includes the baseline.** Emit the full four-column board (`PR | Description | Status | Agent`), exactly as `/sy-list-prs pingpong` specifies. Put only the linked path in PR cells. Put author, head branch, title, and auto-merge state in Description, `·`-separated in separate Markdown spans. Use full `github.com/<owner>/<repo>/pull/<number>` paths. Never elide paths, invent columns, replace the header, condense the board, or insert `<br>` inside cells. A baseline in a different shape than the pulses that follow it cannot be diffed against them, which is the only reason it is printed first.

Start the **agent ledger** here, one row per resolved PR. Record:

- **Stable job key (`sy-babysit-pr:<owner>/<repo>#<number>`) and current live owner's handle**. Match this pair before every later dispatch. Re-invocations, requeues, and recoveries must adopt existing jobs, never duplicate PR ownership.
- Ledger state: `active` / `queued` / `watching` / `terminal`.
- Pass count and **active slot number or queued position**.
- First dispatch time, last pass start/end, and next pass ETA.
- **Latest `## State` block verbatim** from each `/sy-babysit-pr` `pass=single` return. It includes round and per-check counters, `automerge_decision`, and workspace path/kind/ownership.
- `activityAt`, activity band (`active` / `stale`), and queue-aging count.
- **Last rendered pulse snapshot**: Status change marker, color emoji, fragments, and Agent counters. The state block uniquely preserves what a re-invoked per-PR job cannot remember. Build the next round's prompt from it. Seed dead-slot replacement jobs from it. A ledger without it makes every pass a first pass. `/sy-list-prs pingpong` diffs the snapshot to choose `Δ` / `▫️` / `🆕` and write the `Δ` line. After every pulse, replace the snapshot with that output. Compare only against the immediately preceding pulse. Record every PR's ledger state and slot from enrollment onward (Step 3b), including queued and watching PRs. The pulse groups rows by feature set and prints `🌊 slot <N>` on active rows. Missing state silently produces ungrouped rows. Record dispatch, pass-start, pass-end, and next-pass-ETA timestamps immediately. The pulse reads its `started 17:12 · running 22m` clock directly from this ledger; later reconstruction cannot recover it. Never snapshot the elapsed duration itself; it is recomputed at render time and is deliberately excluded from the diff. The ledger is this command's bookkeeping; `/sy-list-prs` only renders it.

3b. **Enroll every PR, rank them, then fill the worker slots from the top of the queue.** The harness caps how many background jobs can run **at once**; it does not cap how many PRs the run covers. Enroll every resolved PR before launching anything. `S` limits simultaneous **active work** only. Merely polling a PR consumes no slot. This is what makes "EVERY open PR in scope" true rather than aspirational, without stranding anything behind a lane.

- **Resolve `S`, the concurrency cap.** It is a property of the harness, never of this command, so this command names no number. Resolve capacity in this precedence order:
  - `cap=<positive-int>` in `$ARGUMENTS`, or a user-named cap in prose.
  - The **harness concurrency cap**, if its own instructions declare one.
  - Otherwise no cap: `S = N`, one job per PR. Reject non-positive-integer values, report the rejection, and use the next source. `S = 0` makes `i mod slot_count` divide by zero. `S < 0` makes assignment meaningless. **Strip `cap=` from `$ARGUMENTS` before any scope parsing**. Never forward it to `/sy-list-prs`. Otherwise Step 1 mistakes it for a PR ref, and delegated renderers mistake it for scope. Say which value you used and where it came from.
- **If the launch is partially rejected, cancel and relaunch — never inject the rejects into a running slot.** Slot prompts are immutable and self-contained (Step 4). Never add PRs to live slots. The dead-slot rule forbids the same mutation for the same reason. When only `k` of `slot_count` jobs actually start:
  - **`k == 0` is a launch failure, not a cap discovery.** Report it and stop — do not set `S = 0`, which makes `i mod slot_count` a division by zero and would "recover" into launching nothing at all.
  - **Cancel the `k` that started and confirm each one is actually terminated before relaunching.** Two jobs on one PR is worse than a stranded PR: they push over each other, double-comment, and race on the same worktree.
  - **Collect what the cancelled jobs already did.** A first pass is short but not empty — a job may already have pushed a fix, posted a comment, or enabled automerge. Seed relaunched slots with each PR's `## State` from the ledger. Jobs report ownership changes immediately for this purpose. This prevents misclassifying previously-enabled automerge as `pre_existing` or repeating completed work.
  - Then set `S = k`, refill from the top of the ranked queue, and launch that set in one message. A cancelled first pass costs almost nothing. Report the discovered cap and the refill, since the new ledger supersedes the one already announced.
- **Rank all `N` resolved PRs by work owed through the AUTHOR lens**, the default. Use `/sy-list-prs`'s canonical `## Work-owed ranking`: P0–P6, activity bands, queue aging, and tiebreakers. Request scheduler data with `pr_list --json --activity`; do not change ordinary `pr_list` calls. Use author tier order, then active before stale and newest `activityAt` first within equal urgency. A stale PR waiting through `3` queue selections, or `1` full run without a pass, receives an aging promotion within its current band and tier. Do not restate or re-derive the ranking here; read it there. Say which lens you used, the activity band, `activityAt`, and aging count when reporting the ledger. Ranking decides **order only** — it never removes a PR from the set.
- **Assign each enrolled PR exactly one state; only `active` consumes a slot:**
  - `active`: a worker runs a full pass.
  - `queued`: a full pass is due, awaiting capacity; consumes no slot.
  - `watching`: nothing actionable; the dispatcher polls fingerprints from the pulse, consuming no slot.
  - `terminal`: merged, closed, or handed to the human. A PR moves between them freely; nothing is ever dropped from the ledger.
- **Launch `min(N, S)` workers from the top of the ranked queue, all at once.** The highest-ranked PRs each get their own worker, so every one of them is serviced immediately. When a worker finishes a pass, its PR moves to `watching` or back to `queued`, the slot frees, and the next PR by rank takes it.
- **Every PR is enrolled before the first job launches.** A resolved PR missing from the ledger is a bug in this step, not a backlog — go back and enroll it. `queued` is not stranded: it is next in line, and the ledger says so.
- **Report the ledger at dispatch** — every PR with its tier and starting state (`github.com/acme/api/pull/51 (P1) active — slot 1`, `github.com/acme/web/pull/7 (P5) queued`). This is the artifact that proves nothing was stranded, and it is the first thing to check when a PR looks ignored.
- **Warn — do not refuse — when the queue is more than 3× the slot count.** `N > 3 × S` means a PR can wait through several passes before its first, so the run stretches. Say so, name the number, and carry on; servicing all of them slowly beats servicing `S` of them and abandoning the rest.

3c. **Concurrent-migration cross-check — run it BEFORE dispatching anything, over EVERY open PR in each repo, not just the ones being babysat.** Once the fan-out is in flight the jobs run concurrently and cannot be handed shared context, and a per-PR job only ever sees its own branch. Merge ordering across a shared migration DAG is a property of the whole set, so the dispatcher is the only thing positioned to compute it.

- **Scope is every open PR in every repo the resolved set touches** — `gh pr list --repo <owner/repo> --state open --json number,url,title,headRefName,author,autoMergeRequest --limit 100` per repo. Use a deliberately wider scope than the babysit set. Unwatched migration PRs can still collide with watched PRs. Existing automerge can land PRs mid-run without any watcher. Filtering to babysat PRs, or to automerge-on PRs, would hide exactly the collisions that break the default branch.
- **Keep the ones that add a migration file** (detection table: `/sy-sync-pr-branch` Step 7 — do not restate it). `gh pr diff <n> --repo <owner/repo> --name-only` per candidate. Zero or one hit across the repo → nothing to coordinate; say so in one line and move on.
- **Record the floor head once, at dispatch,** and hand it to every job: the current migration head on each repo's default branch. The dispatch-time head distinguishes initial staleness from mid-run head movement. That prevents re-parenting every pass instead of once.
- **Two or more migration PRs in one repo → compute a merge order and pass it down.** Rank them by whichever must land first (ready-to-merge and automerge-on first — those land without a human), then hand each job its position plus the full pairing. Whichever lands second re-parents; that is the job's own Step 4 override doing the work, not something the dispatcher fixes. **Never re-parent, push, or reorder anything from here** — the dispatcher coordinates and never touches a branch.
- **Name the pairs in the announcement and in the Step 5 final report,** with each PR's automerge state. An unattended `--auto` PR sitting behind another migration is the single highest-risk row in the set, and the user should see it before an hour of passes starts, not after.

4. **Fan out one background job per SLOT — all at once, in parallel.** Do NOT walk the list sequentially.

   **Dispatch mechanics — this is the step agents get wrong.** "In parallel" is a hard requirement, not a hint:
   - **Emit every slot job in ONE assistant message with `slot_count` tool calls in that same message.** One sub-agent / Task / background-shell invocation per slot, all in a single block. A second message per slot is a sequential loop wearing a parallel costume — that is the failure mode this section exists to prevent.
   - **Never** `for pr in ...; do ...; done`, never "start job 1, wait, start job 2", never a staggered launch. Every slot starts at the same instant.
   - **One slot = one job = one lane. When `N ≤ S`, one slot holds exactly one PR** and this is the classic one-job-per-PR fan-out. Multiple PRs share a slot only when PRs outnumber slots. This is the _only_ exception to "never a single job that iterates the PR list". Iterate **only assigned PRs**, never the whole list or a self-selected list.
   - **Jobs share nothing** — no cwd, no branch, no state file, no conversation. A slot job must never read another slot's result or wait on it. Within a slot, each PR still gets its own worktree; the slot switches between them, it does not merge them.
   - **Give every job an identifying label, and a PR-specialized worker when one exists.** If the environment supports short job labels, use `<PR number> - <head branch> - <author>` for the job's starting PR. Omit author only when you authored every PR in the set. Where the environment offers a worker specialized for babysitting a pull request, dispatch to that one rather than the generic default. Both are cosmetic-only: a run that can do neither is not degraded, and neither ever changes scope, ranking, assignment, or cadence. They exist because a board of identically-named workers is unreadable the moment a fan-out exceeds two slots — the operator cannot tell which lane stalled.
   - **Each slot job's prompt is self-contained.** Pass the **ordered assignment list**, including each PR's tier. For every assigned PR, explicitly include:

- Full PR URL and PR number.
- Resolved `<owner>/<repo>` from `git remote get-url origin`, never folder names.
- Head branch and canonical worktree path `$HOME/.worktrees/<owner>/<repo>/<sanitized-branch>`, as produced by `worktree_create "$BR"`.
- **Every other PR URL across the whole dispatched set**, not merely this slot. `/sy-babysit-pr` Step 2c needs all batch siblings to prevent docs merging ahead of code.
- **Step 2 stack position, when applicable**: bottom-up ancestor PR links and children. The job must know not to merge before its parent.
- **Step 3c migration coordination, when applicable**: dispatch-time floor migration head, other open migration PRs in that repo with automerge state, and this PR's computed merge-order position. A job cannot infer this from its branch alone. Sub-agents start with a fresh context — anything you don't pass, they don't have.
  - **Do not pre-create worktrees from the dispatcher.** Each job owns the worktree lifecycle of every PR it holds (`/sy-babysit-pr` Step 5a create/reuse and cleanup). The dispatcher never runs `git worktree add`, never `cd`s anywhere, and never touches the user's primary checkout.
  - **A cancelled fan-out leaves live worktrees — re-running resumes them, it does not start over.** Jobs killed mid-flight (session ended, run cancelled, machine slept) leave dirty worktrees and unpushed commits at the canonical paths. Treat this as recoverable state, not garbage. `/sy-babysit-pr` Step 5a resumes each item. Step 3b ranks that state **P0**, so resumed runs service it first. Never pre-clean `$HOME/.worktrees` before a fan-out, and never pass jobs an instruction to reset or re-clone.
  - **Report fan-out immediately on launch**. Show Step 3b's ledger with every PR's state, job, and worktree path. Demonstrate coverage of the whole set, not a prefix.

  **Adopt before you dispatch — a slot is a long-lived job, not a per-round spawn.** Every slot job carries the stable key `sy-babysit-prs:slot<i>`, and every PR it holds carries `sy-babysit-pr:<owner>/<repo>#<number>` (see _A job is addressed by a stable key_). **Match keys against existing live jobs before launching anything**:

- Leave running owners alone.
- Resume idle owners with a follow-up turn carrying the next round.
- Create jobs only for keys without live owners. **Record each returned dispatch handle in the ledger immediately**. Only that handle can address the job in later rounds; you cannot reconstruct it afterward. This is what makes re-invoking `/sy-babysit-prs` mid-fan-out re-attach to the running slots instead of doubling every lane and double-pushing every branch. A PR found under two live jobs is resolved by keeping the older and cancelling the newer, reported explicitly.

  **What a worker does — one pass per round, inside the job that already owns the slot.** Dispatch each slot job **once** and resume it for later rounds. Rotate **PR assignments**, never terminate or respawn the job. See _A pass that runs inside a job runs in that job_. Workers run exactly one pass per PR per round, then report. The dispatcher owns sleeping; workers never occupy slots merely awaiting sleep.
  - **Run every round inside the slot job it belongs to — never dispatch a fresh agent per PR per round.** Resuming a slot for round N+1 is a follow-up turn against a warm context that still holds its worktrees, the comment threads it has read, and its counters. Re-dispatching instead produces `PRs × rounds` agents — 10 PRs over 3 rounds is 30 cold agents rather than 10 warm ones, each re-fetching the same diff and re-walking the same threads. A round number in a job's label (`3217 r2`, `3217 r3`) beside a fresh session is the visible symptom that this rule was skipped.
  - **Invoke `/sy-babysit-pr <PR-URL> pass=single round=<n>` per pass**. Add `last=true` when you know this is the PR's final pass. **Paste the previous `## State` block into the prompt under `## Prior state`**. Omit that heading on the first pass. Resumed jobs retaining prior-round context need the block only as a cross-check. `pass=single` runs one pass and returns rather than owning the clock. `last=true` releases workspace cleanup. Prior state preserves counters, automerge decisions, workspace ownership, and fingerprints across passes. Dropping any of the three silently turns a long run into a series of disconnected first passes.
  - **Await every job dispatched or resumed in a turn before that turn ends** (see _Never end a turn with a dispatched job still in flight_). The dispatcher records completion when children return. Ending a turn with an open round freezes completed jobs at "running" on the board. Never issue a round the run has no time left to await: on the deadline, finish the round in flight and report, rather than starting one more.
  - **The dispatcher owns the clock — the run budget is `<<SY_PR_RUN_BUDGET_ROUNDS>>` rounds (one round = one keepalive interval)** from launch, shared by the whole set. Run a full pass for fingerprint changes, first service, or keepalive at least every `<<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` seconds. Also run one final pass before deadline. There is no per-PR pass quota; a busy PR gets many passes and a quiet one few, and both are correct.
  - **Re-rank the queue every pulse** using the same author lens, activity band, and aging rule. Fresh commits, comments, reviews, CI transitions, or approval changes outrank idle peers within the same urgency tier. Active PRs precede stale PRs; newest `activityAt` goes first within the band. A stale PR waiting through `3` queue selections, or `1` full run without a pass, receives an aging promotion within its current band and tier. **Ranking sets which queued PR takes the next free slot — never whether a PR is serviced at all.** Report every promotion.
  - **A PR that reaches a terminal state leaves the ledger's rotation** (merged, closed, or handed to the human). Report it and stop scheduling it.
  - **Never preempt a running pass.** For new inbound work on an `active` PR, mark `dirty_after_pass`. Re-queue it immediately when its worker returns, at the head rather than the back. Cancelling a pass mid-edit is how a half-applied fix, a stale reply, or a duplicate comment happens.
  - **Report each PR's fingerprint and `externally_blocked` back with its `## State` block, every pass.** That is what lets the dispatcher move it to `watching` and stop paying a worker for it (Step 4b). A worker never decides to park itself — it reports state; the dispatcher schedules.

  - Expect long runtimes: the run works its full budget by design. That is the point — do not shorten it, and do not busy-poll the jobs. Collect each result when its job reports back.
  - If one job fails or escalates, the others keep running; never abort the whole fan-out for a single PR. **If a whole slot job dies, relaunch that slot — do not fold its PRs into a live one.** A dead slot frees exactly its used capacity, allowing replacement without exceeding `S`. Moving its PRs to a neighbor doubles that lane's round length and violates "a slot's assignment never changes mid-run". **Confirm death before replacement**. A finished turn means _idle_, not dead. Resume idle slots with a follow-up turn carrying their next round, preserving worktrees, comment history, and counters. See _Resume an idle job; relaunch only a dead one_. Replace only failed, cancelled, or gone jobs. Launch replacements with the dead slot's **remaining** PRs, excluding terminal PRs. Supply each PR's last `## State` from the ledger as a checkpoint. Replacement jobs cannot inherit the old job's context.
  - **Resume per PR from its own `completed_round + 1`.** A mid-pass death leaves that same pass due, not the next one. Re-queue the PR at the head with its last `## State`. Preserve every other PR's counter. This is exactly why the state block carries `completed_round` per PR rather than a single run-wide round number.
  - If whole-run teardown prevents relaunching a dead slot, report its PRs as partially serviced. Include per-PR round counts so the next invocation ranks them P0.
  - **Parallelism is safe because every PR gets its own git worktree** at a rigid path — **`$HOME/.worktrees/<owner>/<repo>/<sanitized-branch>`**, created by `worktree_create` (see One rigid worktree path). The sanitized branch key keeps branches separated, and none of them touch your primary checkout. Never let a job `git checkout` in the main repo.
  - The per-PR command owns the pass. This wrapper owns only which PRs run in which lane and when — if the per-PR flow needs to change, edit `/sy-babysit-pr`.

4a. **Ping-pong every 10 minutes until the run ends.** Fan-out uses the full `<<SY_PR_RUN_BUDGET_ROUNDS>>`-round budget. While waiting, the dispatcher maintains visible pulses. Never sit silent or busy-poll jobs. The pulse is also where the Step 4b fingerprint probes ride, on the `<<SY_PR_POLL_INTERVAL_SECONDS>>`-second cadence.

- **Cadence: one pulse every 10 minutes**, from dispatch until the last job reports. Three pulses per babysit pass, so a sleeping job still shows a live heartbeat with its next-loop ETA.
- **Render with `/sy-list-prs pingpong <same-scope-token>`, passing the current agent ledger.** Same scope token as Steps 3 and 3a, so every pulse covers exactly the dispatched set. Never hand-roll the board.
- **Refresh the Status column from GitHub, not from the jobs.** Re-run the cheap `gh pr view` status calls `/sy-list-prs` already uses. **Never `write_agent` / message / interrupt running jobs for status**. That wakes passes and corrupts cadence; see Step 4's busy-poll rule. Read job state only from results the jobs have already reported.
- **Update the ledger immediately from arriving reports**. After pass N, move the PR to `🔍 WATCHING` or `⏸️ WAITING` with next-check ETA. Final reports move it to `✅ COMPLETED` / `⚠️ ESCALATED` / `❌ FAILED`. A queued PR with no pass yet stays `⚪ NOT STARTED` with its queue position. Between reports, derive `IN PROGRESS` vs `WAITING` and the next-check ETA from the poll cadence rather than leaving the cell blank.
- **A pulse is display-only.** It never dispatches, retries, cancels, merges, comments, or re-assigns a slot. If a pulse shows a job wedged, say so in that row and let the human decide. A pulse only reports **dead** slots. Step 4 handles relaunch outside the pulse. Relaunch the dead slot; never relocate its PRs.
- Stop pulsing when every row is terminal (`✅ COMPLETED` / `⏭️ SKIPPED` / `⚠️ ESCALATED` / `❌ FAILED`), then go to Step 5. **`⏸️ WAITING_AFTER_SKIP` is not terminal** — that PR still has passes scheduled, so the pulse keeps running. **`🔍 WATCHING` is not terminal either** (Step 4b).

4b. **Watching — a PR with nothing actionable is polled by the dispatcher and holds no worker.** Human-gated PRs waste worker capacity through repeated worktree wakeups, diff reads, comment scans, and no-op reports. Three such PRs can block a fourth PR's fresh review comment from service. Nothing an agent can do moves any of them; only a person clicking, or another PR merging, does. Replace unnecessary workers with two `gh` calls per PR. Give freed slots to PRs with actionable work.

- **Move PRs to `watching` when their latest `## State` reports `externally_blocked`**. The per-PR job applies `/sy-babysit-pr` Step 12a's enumerated cases. Never second-guess that decision here. Watching is per PR, not per lane: one blocked PR frees its slot immediately, whatever the rest of the set is doing.
- **Never move PRs to `watching` mid-pass or with state recording unpushed commits or dirty workspaces**. Such PRs have outstanding work and cannot qualify as externally blocked. Let its worker finish and report first.
- **Prefer an idle, addressable job over a terminated one.** Idle jobs retain worktrees, read threads, and counters. Resume with a follow-up turn instead of a fresh agent reconstructing context from summaries. See _Resume an idle job; relaunch only a dead one_. An idle job holds no slot. Terminate only when the harness cannot hold an idle job, and say so when you do — the ledger requirement (Step 3a) is what makes that fallback safe.
- **The watch runs inside the pulse's existing fetch.** Step 4a already re-runs the cheap `gh pr view` status calls for every row, so the fingerprint costs one extra `gh api .../pulls/<n>/comments?per_page=1&sort=updated&direction=desc` line per watched PR and nothing else. Compute the digest exactly as `/sy-babysit-pr` Step 12a defines it — same two commands, same string comparison. Do not invent a second fingerprint here.
- **The pulse itself stays display-only.** It renders; it never dispatches. This step schedules, it happens to reuse the pulse's fetch, and the only thing it may launch is a worker for a PR **it moved to `watching` itself**. It never relaunches a dead job (Step 4 owns that) and never merges, comments, or pushes.
- **Any fingerprint change re-queues that PR immediately, at the head of the queue.** Resume its idle job with a follow-up turn when it is still addressable; replace it only when it is gone, seeded from the ledger's `## State` block. Report which PR moved and which field flipped (`github.com/acme/api/pull/51 — human approval gate cleared (reviewDecision none→APPROVED) — requeued, slot 2`).
- **A merged wave blocker is a fingerprint change, and the requeued pass is what promotes.** The probe checks every named blocker (`/sy-babysit-pr` Step 12a). A blocker's `OPEN → MERGED` triggers a full pass. That pass runs `/sy-babysit-pr` Step 4a in order:
  sync → CI green → `gh pr ready` → drop `WIP: DO NOT MERGE — ` → rewrite `## Blocked on`. Keep wave-blocked PRs enrolled for this reason. Fingerprints prevent watched wave-2 PRs from ending the run unpromoted because they never woke. The dispatcher notices; it never promotes anything itself.
- **A watched PR still owes its keepalive.** Give it full passes at least every `<<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` seconds and once before deadline. The dispatcher enforces this because watched PRs have no worker job. A run that ends on an unverified probe has not finished.
- **Say what it saved.** Show watched rows as `🔍 WATCHING`, including blocker and next-check time. Step 5 must list every watched PR, watching duration, awaited event, and worker dispatches avoided. Watching is a reported state, never silence.

4d. **A worker's stop-and-ask is surfaced to the operator, and revalidated before it is repeated.** Park PRs returning `needs_user` in `## State` as `watching`. Do not fix the blocked decision. Retain probes and keepalives. Show the operator; sub-agent reports can scroll past. Copy the block verbatim into the ledger and mark the row `NEEDS_USER`. Repeat its reason, exact message, and `Next:` line in **every** pulse and the final report. Never open prompts or block the run awaiting answers. Never post labels, statuses, reviews, or comments purely to record this state on GitHub. **Every PR being terminal or `NEEDS_USER` is not a stop condition** — print the outstanding questions together, then keep sleeping and probing to the deadline. Fingerprint changes or keepalives dispatch revalidation through `/sy-babysit-pr` Step 2b. Changes include user answers, reviewer withdrawals, or approvals. Return `cleared` PRs to the queue. The run ends only on the deadline, every PR `MERGED` / `CLOSED` in explicit-ref scope, or the unreachable-service stop.

- **Revalidate before repeating a claim from an earlier run.** Treat startup `needs_user` memory as a hypothesis. Paste it into that PR's next pass. Let `/sy-babysit-pr` Step 2b re-fetch the source and resolve `current` / `cleared` / `changed` / `conflicted` / `stale_unknown`. Render the verdict, never the stale claim alone. A `cleared` verdict re-queues the PR normally and names the comment that cleared it.
- **`NEEDS_USER` is a local pause, not a GitHub state.** The PR may be green, approved, and mergeable to everyone else; only this run is holding off on it. Render it distinctly from `⚠️ ESCALATED` (a job that stopped on its own error) and never as `⏭️ SKIPPED`.

4c. **Stop the run on the deadline, on a fully terminal ledger, or on an unreachable service.** End the run only for these conditions:

- Every enrolled PR is `terminal` **and scope used explicit PR refs**.
- The `<<SY_PR_RUN_BUDGET_ROUNDS>>`-round budget expires, after a final full pass on every nonterminal PR.
- GitHub or the model service remains unreachable for `<<SY_PR_RETRY_MAX_FAILURES>>` consecutive attempts, `<<SY_PR_RETRY_INTERVAL_SECONDS>>` seconds apart. On the unreachable stop, report `"GitHub or model service unreachable — stopping with resumable state"`, never a local network cause you cannot verify. On **every** stop, save the ledger in each PR's `<<LLM_ROOT_FOLDER>>/pr_babysits/` memory. Include PR state, latest `## State`, fingerprint, and queue order. Fresh invocations must resume rather than restart.

5. **Final report:** Emit the **closing ping-pong** with `/sy-list-prs pingpong <same-scope-token>`, final ledger, and `Next ping-pong: — (final)`. Follow with one `/sy-list-prs table <same-scope-token>` render. Briefly summarize PRs skipped as already green, processed, or needing human attention. Include every PR's pass count, final ledger state, and worktree path with reused/created status. **Name every PR that spent time watching**:
   `github.com/acme/api/pull/51 watched 3h12m — blocked on a human approval gate; 41 probes, 0 worker dispatches, requeued once when <link> merged`
   Note worktrees preserved because they pre-existed. **Name every wave promotion**:
   `github.com/acme/web/pull/7 promoted on round 6 — blocker github.com/acme/api/pull/40 merged → synced, undrafted, WIP prefix dropped`
   Name every wave PR still watching and its remaining blocker. Report any promotable PR left unpromoted; never omit the miss. **Report agent reuse too**: which jobs were adopted or resumed rather than freshly dispatched, and any duplicate job cancelled. **Verify and explicitly report service for every resolved PR**. Compare row count with Step 1's resolved count. Enrollment must prevent mismatches. Name every zero-pass PR and explain why. A watched PR is a serviced PR: report it as one, never as skipped or missing. The run therefore always brackets itself: pulse at the start (Step 3a), pulse every 10 min (Step 4a), pulse at the end.

## Rules

- This command is a dispatcher. The per-PR loop lives in `/sy-babysit-pr` — do not re-implement it here.
- **A slot is a long-lived job that is adopted, resumed, and reused — never re-spawned per round (Step 4).** Give every slot and PR a stable job key. Enumerate live jobs and match keys before dispatch. Mid-fan-out re-invocations must reattach to running slots, never duplicate lanes or PR ownership. A job that finished its turn is **idle, not dead**: resume it with a follow-up turn, replace it only when it is failed, cancelled, or gone. Run passes **inside** the slot job. Both `pass=single` and "already inside a dispatched job" force `/sy-babysit-pr` inline. Spawning children creates `PRs × rounds` agents despite existing job context. Use these canonical rules:
- _A job is addressed by a stable key_.
- _Resume an idle job; relaunch only a dead one_.
- _A pass that runs inside a job runs in that job_.
- **Wave promotion is detected here and performed there.** The dispatcher sees the whole set. Resolve the wave graph at announcement (Step 2) and pass blocker links to each blocked PR's slot job. A blocker's `OPEN → MERGED` fingerprint change requeues that PR on the next probe (Step 4b). The promotion itself — sync, CI green, `gh pr ready`, drop the `WIP: DO NOT MERGE — ` prefix, rewrite `## Blocked on` — is `/sy-babysit-pr` Step 4a, on that PR's own pass. **The dispatcher never edits a title, never undrafts, and never rewrites a body.** A wave-2 PR that ends the run unpromoted while its wave-1 blocker merged hours earlier is the failure both halves of this exist to prevent.
- **Prose-only PRs in a fan-out do NOT self-merge — they wait for their batch.** `/sy-babysit-pr` Step 2c only enables `--auto` on a _standalone_ docs / comment / whitespace PR, and every PR in this dispatched set counts as a companion of every other. So a docs PR inside a fan-out is deferred until its siblings merge or close, then self-merges on a later pass. That is what keeps documentation from landing ahead of the code it describes. A fan-out of exactly one PR is standalone by definition and may self-merge immediately. Say which docs PRs are deferred in the Step 2 announce; the dispatcher itself never enables or disables automerge.
- **Migration collisions are the dispatcher's to see and the jobs' to fix (Step 3c).** Scan **every** open PR in each repo, not merely babysat or automerge-enabled PRs. Per-PR jobs see only their own branches. Unwatched PRs routinely break default. Compute the merge order, record the floor's migration head at dispatch, and hand both to every affected job. The dispatcher never re-parents, never pushes, and never reorders a merge itself: whichever PR lands second re-parents via its own `/sy-babysit-pr` Step 4 override.
- **Base-branch sync is already included — never bolt it on.** Each job first delegates `/sy-babysit-pr` Step 5 to `/sy-sync-pr-branch`. It merges default and, for stacked PRs, every ancestor branch before any other job work. Do not call `/sy-sync-pr-branch` from the dispatcher, do not `git merge origin/main` here, and do not add a "sync pass": the same sync would run twice and race the jobs' own worktrees.
- **Preserve approval by default.** Apply this restriction when all conditions hold:
- CI is not failing.
- The base branch has no conflict.
- The migration head is current.
- No non-self reviewer has an active `CHANGES_REQUESTED` review.
- Fewer than `<<SY_PR_REVIEW_CHANGE_THRESHOLD>>` unresolved actionable change comments exist.
  In that case, workers must not fetch, reply to, resolve, dismiss, or re-request ordinary review comments. Never push code merely to address those comments under these conditions. Only those five blocker states activate `/sy-babysit-pr` Step 6, and then it handles only comments relevant to the active blocker; all other review feedback remains untouched.
- **Parallel means one message, `slot_count` tool calls — not `N` (Step 4 Dispatch mechanics).** The job count is `min(N, S)`, never the PR count: launching one job per PR past the cap is what strands the tail. If the transcript shows the slot jobs starting one message at a time, the fan-out was sequential and must be relaunched. Self-contained prompt per slot, no shared state.
- **An empty or fully terminal ledger ends the run only in explicit-ref scope.** When `$ARGUMENTS` named specific PRs, every one `MERGED` / `CLOSED` is terminal. Every other scope is a search (repo, author, org, pwd, empty), and a search that finds nothing now can find something next round. In those modes, zero open PRs or an entirely merged/closed ledger means an **idle round**. Report one line, `sleep` the keepalive, re-resolve scope, and enroll new PRs. Continue until deadline or unreachable-service stop. Never write `Stopping because the only reachable PR merged` in a search scope.
- **An idle set is a reason to sleep, not to stop.** Use real blocking waits: `sleep <<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` per slot round, `sleep 600` per pulse. Re-resolve scope at every round's start to enroll mid-run PRs. Never end with a user question. A dispatcher whose harness has no detached jobs runs the rounds inline with real sleeps instead of cancelling them; stopping with rounds still owed is a failed run.
- **Every non-placeholder PR resolved for babysitting is enrolled before anything launches — never dropped (Steps 1p / 3b).** One worker per PR while slots last; past the concurrency cap the surplus is `queued` by rank and takes the next slot a worker releases. A slot is held only by a pass actually running: a `watching` or `queued` PR costs nothing, which is what makes covering the whole set affordable. A PR that ends the run with zero passes is a bug in this command, not an acceptable outcome. Placeholder drafts dropped by Step 1p are the one intentional exclusion, and they must be named in the announce and final report.
- **Order comes from the work-owed ranking, defined once in `/sy-list-prs`.** Do not restate the tiers here, do not invent a second ranking, and never use it to skip a PR — it sets service order only. Re-rank inside a slot each round; never move a PR between slots mid-run.
- **A worker runs one pass per round and hands the slot to the next PR — the job it runs in is not re-spawned (Step 4).** Run every `/sy-babysit-pr <url> pass=single` pass **inside** its existing slot job, with prior state pasted in. Round N+1 resumes that job; never dispatch a replacement merely for another round. Workers sleeping through cadence while holding slots recreate starvation inside jobs. Fresh agents per PR per round recreate agent explosion, even with round-number labels.
- **Babysit all resolved PRs in parallel background jobs — never a sequential for-loop** (see Fan out multi-PR work in parallel). Use one worktree per branch at `$HOME/.worktrees/<owner>/<repo>/<sanitized-branch>` through `worktree_create` (`/sy-babysit-pr` Step 5a). Sanitized branch keys prevent PR collisions within or across slots. Share nothing and never touch the user's primary checkout.
- **A fan-out run is long by design.** It works the full `<<SY_PR_RUN_BUDGET_ROUNDS>>`-round budget unless every PR goes terminal first. Don't truncate jobs, don't busy-poll them, and don't declare the fan-out done until every PR has reported.
- **An externally blocked PR is watched by the dispatcher and holds no worker (Step 4b).** For human-approval waits, fold two read-only `gh` calls per probe into the pulse's existing fetch. Give that PR's slot to actionable work. It is requeued at the head the instant its fingerprint moves, and still gets a keepalive pass at least every `<<SY_PR_KEEPALIVE_INTERVAL_SECONDS>>` seconds plus one before the deadline. Never move a PR to watching mid-pass, and never report a watched PR as skipped. The mechanism and the fingerprint are defined once in `/sy-babysit-pr` Step 12a; the externally-blocked call belongs to the per-PR job, the scheduling to this one.
- **Ping-pong is mandatory, not optional (Steps 3a / 4a / 5).** Every run pulses before dispatch, every 10 minutes while jobs run, and once at the end. A long async fan-out with no heartbeat is indistinguishable from a hung one. Keep pulses read-only: refresh PR status through `gh` and read existing job reports. Never message, wake, or interrupt running jobs. Never act on pulse findings inside the pulse.
- **Ping-pong layout is owned by `/sy-list-prs pingpong`.** This command owns and passes the agent ledger. Include job state, loop number, slot number/position, pass timestamps, next-loop ETA, and last rendered pulse snapshot. `/sy-list-prs` owns columns, icons, change markers, feature-set grouping, and sorting. Do not hand-roll a different board.
- **Table output is owned by `/sy-list-prs`.** Both the pre-flight render (Step 3) and the final report (Step 5) reuse its `table` format. Pass the same scope `$ARGUMENTS` to `/sy-list-prs table` so the rendered set matches the resolved PR set exactly. Do not hand-roll a different table layout.
- **First token of `$ARGUMENTS` decides the mode — no mixing.** PWD-keyword + explicit refs in the same call is an error; pick one. Empty and PWD-keyword modes both scan cwd + nested repos; explicit-list mode does not filter by author (you asked for those specific PRs).
- **Surface authors when the resolved set isn't all yours** (see Show PR authors). Explicit-ref mode is author-agnostic, so it can silently pull in someone else's PR — name the author on every row and in the summary whenever the set is mixed. The `/sy-list-prs table` renders (Steps 3 and 5) already add an `Author` column in that case.
- **Always resolve `<owner>/<repo>` via `git remote get-url origin`, never from the folder name (see Repo Identification).** Applies to PWD scan (delegated to `/sy-list-prs`) and to bare-`#<n>` ref expansion.
- **Stacked PRs still fan out in parallel — do NOT serialize them, and do NOT sync them from the dispatcher.** This contains existing stacks; it does not authorize new ones. Each worker syncs floor-then-ancestors downhill into only its own branch, so workers never write the same ref. Later probes pick up parent pushes. Never wait on or message a parent job, or merge/retarget an ancestor from the dispatcher.
- **Stacks land bottom-up, and only the human lands them.** A stacked PR that goes green + approved is reported as blocked on its parent (`/sy-babysit-pr` Step 4) — no job merges it, and no job enables automerge on it. When a parent does merge, GitHub retargets its children automatically and the children's next pass re-resolves the chain. Say which dispatched PRs are stacked, and on what, in the Step 2 announce so the merge order is visible before the run starts.
