# bashrc — Architecture

## High-Level Overview

`synle/bashrc` is a personal dotfiles and shell-environment bootstrapper targeting macOS, Ubuntu/Debian/Mint, Arch/SteamOS, RHEL/Fedora, Windows (PowerShell, MinGW, WSL), ChromeOS, and Android Termux from one codebase. Setup engine: Node.js → bash pipeline — `run.sh` sources env detection, then `cat software/index.js | node | bash`. `index.js` discovers scripts in `software/scripts/`, emits bash to stdout; bash installs tools, writes configs, and assembles `~/.bash_syle` from `# BEGIN`/`# END` markers.

Also ships a Vite + React webapp (`webapp/`, sources in `src/`) at https://synle.github.io/bashrc/, plus Vitest suites (`software/tests/`, `tests/`). Build artifacts land in `.build/`, regenerated by CI across five OS runners.

## Important Files

- **`run.sh`** — Entrypoint. Local vs remote mode, flag parsing (`--files`, `--preset`, `--debug`, `--refresh`, `--dryrun`, `--remove`), drives the node→bash pipeline.
- **`Makefile`** — Setup / validation / CI targets.
- **`software/index.js`** — Dual-purpose: shared utility library (parsers, IO, network, platform detection, tagged templates) AND bootstrap orchestrator discovering + running scripts.
- **`software/common.js`** — Helpers shared with individual scripts.
- **`software/bootstrap/common-env.sh`** — Sets `REPO_PATH_IDENTIFIER`, `REPO_BRANCH_NAME`, `ALL_OS_FLAGS`; consumed by engine and `vite.config.js`.
- **`software/scripts/_init.js` / `~cleanup.js` / `~wrapup.sh`** — Lifecycle brackets: init preamble; cleanup flushes profile blocks, strips unfilled markers, finalizes `~/.bash_syle`.
- **`software/tools/build-include.js`** — Marker-based include system + `// {{theme.key}}` color tokens in JSONC.
- **`install.sh`** — Public installer wrapper (`curl | bash`).
- **`vitest.config.js` (+ 4 sibling configs)** — One config per test suite.
- **`AGENTS.md` / `DEV.md` / `README.md`** — Rules / dev quick-start / user overview.

## Execution Pipeline

1. **Bootstrap.** `run.sh` detects local vs remote mode (presence of `software/index.js`). Remote fetches `run.sh` + `software/` from raw.githubusercontent into `$BASHRC_TEMP_DIR` (rooted at `$BASHRC_TEMP_ROOT_DIR`, `/tmp` with mktemp fallback on locked-down hosts) and re-execs.
2. **Arg pre-scan.** Bash extracts flags it acts on directly (`--debug`, `--verbose`, `--dryrun`, `--force-refresh`, `--remove`); the rest JSON-encoded into `BASHRC_RAW_ARGS`.
3. **OS detection.** `_detect_os` writes `is_os_<name>=1` vars. Order matters — `is_os_ubuntu` is the Debian-family catch-all and stays last. Tested by `osDetection.spec.js`.
4. **Env sourcing.** `common-env.sh` exports shared constants; inlined into `run.sh` via BEGIN/END so it works standalone.
5. **`node | bash`.** `index.js` runs as library (defines globals) and runner (enumerates scripts, evaluates each, writes bash to stdout).
6. **Bash execution.** Installs tools, writes configs, registers profile blocks. `ScriptSkipError` aborts one script without killing the run.
7. **Cleanup & wrapup.** `~cleanup.js` flushes buffers, strips unfilled markers; `~wrapup.sh` dumps CI logs, stamps `run_timing.json`.

Output redirection: only `emitBash()` writes stdout; everything human-readable uses `log()` (stderr).

## Script Discovery & Ordering

`getSoftwareScriptFiles()` (index.js ~3918):

1. Drop `.common.js` (shared helpers), `.standalone.js` (on-demand); `_full-setup.*` unless `IS_SETUP`; `advanced/` on limited-support OSes.
2. Keep top-level scripts + only matching OS subdirs.
3. Order: `_init` → `_full-setup` → `_only` → lexical → `~cleanup`/`~wrapup`.

Consecutive same-type scripts batch into one bash subshell; `.su.js` bundled so sudo prompts once. `--files=` bypasses ordering and always appends `~refresh-source.standalone.js` to refresh SOURCE blocks.

## Profile Assembly

Scripts never write `~/.bash_syle` directly — they buffer via `registerWithBashSyleProfile(configKey, content)` (append/replace a BEGIN/END block), `registerPlatformTweaks(platform, content, subKey?)`, autocomplete/powershell variants, and `removeFromBashSyleProfile` (for `--remove`). All writes accumulate in `_profileBlockBuffer`, flushed once per bundle + in `~cleanup.js`. Duplicate `configKey` throws. Empty marker pairs pre-placed in `profile-core.sh` / `profile-advanced.sh` so blocks update in place.

## BEGIN/END Inlining vs SOURCE Runtime Includes

Two distinct mechanisms:

| Mechanism | When | Use case |
| --- | --- | --- |
| `# BEGIN <path>` / `# END <path>` | Build time (`make format_build_include`) | Inline a partial into a generated/checked-in file (e.g. `common-env.sh` into `run.sh`). Edit the source file — block contents overwritten on next format. |
| `# SOURCE <path>` | Runtime (`readText()`, every run) | Pull live shell into `~/.bash_syle` each run without full setup. Only the marker is committed; materialized block lives in generated profiles only. |

Rule: shipped-at-build-time config → BEGIN/END; live shell refreshed each run → SOURCE.

## Preset Composition

`presets.jsonc` is JSONC (stripped by `stripJsoncComments` before parse). Each entry: optional `files[]`, recursive `presets[]`, `description`. `expandPresetFiles()` flattens with cycle detection; cycles throw at parse time (`presets.spec.js` guards).

CLI resolution precedence (`parseRawArgs`): `--files=` strict script (three tiers: exact path → basename → partial regex); `--preset=` strict with substring fuzzy fallback; bare `<x>` script-first then preset; bare `@<x>` strict preset. Script wins collisions — use `@llm` to force the preset.

Composites: `lightweight`, `heavyweight` (= all building blocks: `editors`, `emulators`, `apps`, `browsers`, `terminal`, `prompt`, `llm`).

## Build & Release Flow

CI = `.github/workflows/build-main.yml`, phased:

1. **Prep** (Ubuntu) — format + build-include + webapp build; uploads prep patch + dist.
2. **Build ×5 parallel** (ubuntu, rhel, arch, debian, mac) — apply patch, run ci-build, upload `.build/` + per-OS profile; default-branch pushes mirror profiles to the `binary-cache` release.
3. **Publish** — merges `.build/` artifacts (excluding untracked profiles), amends HEAD force-with-lease, copies profiles into `dist/`, deploys Pages, stamps status on amended SHA.
4. **Test** — unit/profile/smoke/buildconfig/coverage suites; job summaries render binary verification (`check_binary_required` fails, `check_binary_warn` doesn't), per-script timing, coverage matrix; tags `v0.YYYYMMDD.<run_number>`.

Because Publish amends HEAD, the SHA changes after CI — `git pull --rebase` before pushing again. No app-style releases; distribution via rolling `main` (`curl | bash`) + Pages.
